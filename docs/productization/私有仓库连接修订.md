# 私有仓库连接修订

Owner 指出其最重要的来源是私有仓库，原先只支持公开仓库的选择不能满足真实需求。本修订直接补齐私有来源，不让 Owner 再搬运数据或复制 Token。

## Owner 体验

在 Sources 连接公开或有访问权限的私有仓库。优先复用 Git for Windows / Git Credential Manager 已保存的 GitHub 登录；没有登录或过期时，Sources 与连接弹窗均提供官方浏览器登录入口。当前 Owner 机器已有可用登录，已成功读取指定私有仓库，无需重新授权。私有来源卡片明确标为“私有”。

Source → Today → 可编辑建议 → Owner 确认 → Track 流程保持不变。只获取信息，不向 GitHub 写回。权限不足/登录失效明确显示；失败保留已有快照与个人状态。Actions 权限不足时标为验证不可用，不把它当作通过，也不阻断提交/PR 信息。

## 凭据和数据边界

- 凭据由 Windows/GCM 保管，Workbench 不新增凭据存储，不修改 SQLite schema/version/identity/restore contract。
- Token 仅在主进程内存中短暂用于固定 `https://api.github.com` 请求，禁止跟随重定向；不返回 renderer，不进入来源 payload、数据库或备份。子进程异常不传播原 stdout/stderr/cause，避免包含凭据。
- 后台只读取已有登录，不弹授权窗口。浏览器登录必须由 Owner 点击；Workbench 不清除共用 Git 登录，不自动强制重登。实际登录命令中的 `--force` 仅用于 Owner 主动点击“重新登录”后更新凭据。
- 没有 GCM 时公开仓库仍可匿名使用，私有仓库会提示安装 Git for Windows/登录。标准 Windows 安装路径优先，其他安装位置使用 PATH；这台 Owner 机器已验证标准路径可用。
- 私有事实内容仍是本地 canonical 数据，也会进入 Owner 的备份，连接表单明确提示。公开工程证据只记录布尔结果/流程检查/指纹；私有标题、提交、正文、截图未上传公开仓库。
- 隔离 packaged 测试默认不读取本机 GCM。只有显式本地 `--private` 模式启用真实凭据，仓库地址由环境变量指定；CI 不访问 Owner 私有库。
