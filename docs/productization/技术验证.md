## 保持的契约

SQLite 仍是唯一 per-user canonical store。外部快照与 Owner 的 Track 分开保存。没有远端写回、第二个数据库或隐式目标/阶段/生命周期修改。旧 v1/v2/v3 DDL、旧 ID、occurrence identity、date-only/wall-time 规则以及 Store 的 backup/staging/restore 实现未修改。

v4 只追加 project_sources 与 project_updates。Architecture 的 ordered migration/safety 契约和字段级 DDL 实现权限允许这类增量；无需变更 frozen storage ownership/identity contract。新增来源 ID、快照 ID 使用 UUID，仓库身份额外检查 GitHub numeric ID。单源最多保留 20 个证据快照，不承诺历史活动产品。

升级失败事务回滚；升级前安全快照仍可用旧版读取。新版可 staging 升级旧备份再恢复。若需退回旧程序，应先另存当前 v4 完整备份，再用升级前 v3 安全快照配合旧程序；旧程序不能直接读 v4，新版产生的数据不会自动反向降级。

## 可重复命令

```
npm ci --no-audit --no-fund
npm run lint
npm run typecheck
npm test
npm run test:integration
npm run build
npm run package:win
npm run test:packaged
npm run test:reality
```

`test:packaged` 先运行原全部 GUI/可靠性回归，再运行新增项目流程。新增 fixture 仅替换主进程 fetch；连接、查看、确认、断开、备份/恢复均经普通 UI/IPC。`test:reality` 用同一 packaged exe、独立临时 userData，通过真实 GitHub API 做连接→提炼→确认→Track→backup/restore→restart。不会接触 Owner 当前数据库。原生文件选择器以返回值替换，不声称真实鼠标托盘 UAT。

## 当前局限

公开 API 匿名请求有共享 IP 限额；后台三来源每半小时约 12 请求，手动刷新仍可能触发限额。失败不丢本地数据。无私有库、认证、PR diff 或文档语义分析；有限窗口可能遗漏较旧开放 PR 或 run，界面明确读取范围。30 分钟后台检查在应用运行时进行，操作系统休眠后下次检查补上；renderer 30 秒刷新本地投影。原始事实标题可能无信息量，规则摘要不负责猜测产品进度。
